## Logical-state camera principle

A camera may eventually be associated with each **logical presentation state**, even when several states reuse one physical anchor:

`logical_presentation_id → physical_anchor_id → camera_id → validated_route_id`

Camera authority remains spatial; UI code requests a logical destination and does not invent coordinates.

## Return / anti-trap contract

Every logical presentation state must eventually provide device/browser-friendly return behavior:
- visible Back/Return;
- keyboard-safe return where appropriate;
- mobile-safe controls;
- compatible browser-history behavior;
- physical reverse traversal through the validated spatial route.

The user confirms a logical journey once. Intermediate doors do not generate additional confirmations.

## Not proven here

- door adjacency
- walkable routes
- house-transfer corridor
- final cameras
- runtime spatial integration
- retirement of existing navigation
