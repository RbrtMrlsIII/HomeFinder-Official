# E5 — Canonical Artifact & Build Provenance Findings

**Date:** 2026-09-01  
**Milestone:** E5 — Canonical Artifact & Build Provenance  
**Scope:** HomeFinder repository, GitHub Actions, PR/branch lineage, Vercel deployment provenance, existing artifact ownership, and E5 execution-system records.

## Process

Observe → Record → Understand → Classify → Align → Validate → Endorse → Advance.

This gate evaluates provenance infrastructure before declaring it complete. A provenance record may establish artifact/build/deployment facts, but it does not promote runtime validation or endorsement beyond the evidence actually obtained.

## Findings

### E5-F01 — Existing artifact evidence is real but was previously outside the canonical registry
**Observed:** GitHub Actions run `33451823171` produced artifact `9780126370`, `homefinder-p04-playwright-report`, SHA-256 `d4e59131592c7af694b222726c603c3fa5683cf392cd1e876953632402cdec67`.

**Understanding:** The run completed with infrastructure/setup steps successful, the focused P04 browser validation failed, and the Playwright evidence upload succeeded. The artifact therefore proves evidence production/upload, not runtime success.

**Classification:** SYSTEMIC / CI / EVIDENCE / DERIVED.

**Disposition:** RETAIN and register canonically.

### E5-F02 — Artifact source commit differs from the current branch head
**Observed:** The GitHub artifact is attached to workflow head SHA `5c9903113010d88c6a91677dc3709552bc297ed0`, while the current P04 branch later advanced to `d2149c79d8197d6ee7879f9ad677bd959808db7f` and beyond during this E5 gate.

**Understanding:** Provenance must preserve the exact source commit of an artifact rather than attaching it implicitly to the latest branch head.

**Classification:** SYSTEMIC / GIT / PROVENANCE.

**Disposition:** RETAIN as explicit source lineage in the registry.

### E5-F03 — Vercel provides an independent deployment provenance surface
**Observed:** Vercel project `home-finder-official` is linked to `RbrtMrlsIII/HomeFinder-Official`. Deployment `dpl_5Fi2KT76WLu7zUFH1wcu3yPPU6Nj` is `READY` and records Git ref `p04/glb-runtime-restored-2026-09-01` and Git SHA `d2149c79d8197d6ee7879f9ad677bd959808db7f`.

**Understanding:** This proves a Vercel deployment reached READY for a precise repository state. It does not prove P04 browser/GLB runtime success.

**Classification:** BOUNDED / DEPLOYMENT / DERIVED.

**Disposition:** RETAIN and register canonically.

### E5-F04 — Provenance helper schema was initially incomplete
**Observed:** The first helper lacked explicit tooling and endorsement-state fields despite the E5 specification requiring them.

**Understanding:** The implementation and schema must describe the same provenance contract.

**Classification:** LOCAL-to-BOUNDED / TOOLING.

**Disposition:** CORRECTED in `build-provenance.py` before E5 endorsement.

### E5-F05 — Empty canonical registry was a closure defect
**Observed:** `builds.json` initially contained no records even though real GitHub evidence existed.

**Understanding:** A registry that only defines a schema is not yet a functioning provenance system.

**Classification:** SYSTEMIC / MACHINE STATE.

**Disposition:** CORRECT by recording real CI and Vercel provenance entries.

### E5-F06 — Existing HomeFinder artifact ownership must remain unchanged
**Observed:** `master/HomeFinder.sh3d` remains physical authority; established GLB/artifact paths already have project-specific semantics.

**Understanding:** E5 requires provenance, not repository restructuring.

**Classification:** PROTECTED / AUTHORITY.

**Disposition:** RETAIN; no relocation.

### E5-F07 — P04 runtime endorsement remains outside E5
**Observed:** The referenced P04 CI run failed its renderer-mount assertion and did not prove target/camera/GLB-loading assertions.

**Understanding:** E5 provenance can faithfully record this failure but cannot convert it into a P04 pass.

**Classification:** PROTECTED / RUNTIME / ACCEPTANCE.

**Disposition:** DEFER to P04.3–P04.6.

## E5 adoption decision

**Adopted:** canonical provenance schema; real CI artifact records; Vercel deployment records; source-commit lineage; explicit status/endorsement distinction; existing artifact ownership preservation.

**Rejected:** generic build-directory migration; treating deployment READY as runtime validation; replacing existing SH3D/GLB authority; separate duplicate handover or knowledge authorities.

## Knowledge distillation assessment

**New durable knowledge identified:** no new project rule is required beyond the rules already established by E1/E4 and the existing project knowledge authority. E5 operationalizes those rules into machine-readable provenance. The exact observed GitHub/Vercel records remain in E5 evidence and registry state.

## Gate disposition

E5 is eligible for endorsement after the canonical registry contains real GitHub and Vercel records, the helper matches the schema, validation evidence is recorded, and whole-project continuity is synchronized.
