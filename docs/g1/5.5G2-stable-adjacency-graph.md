# 5.5G.2 — Stable Candidate Adjacency Graph

## Status
**GRAPH BUILT / ROUTES NOT VALIDATED**

This gate converts the G1 physical adjacency evidence into stable node/edge records. It does not implement navigation and does not promote any route.

### Graph rules

- Room nodes use `level::room-label-or-id`.
- Exterior is an explicit `EXTERIOR::level` node.
- House boundaries are explicit candidate nodes.
- Each edge retains its source SH3D door ID.
- Adjacency remains `NOT_VALIDATED`.
- Self-loops and unsupported one-sided records are excluded.
- No edge is invented to connect disconnected components.

### Results

- Physical room nodes represented by graph: **29**
- Candidate adjacency edges: **29**
- Explicit house boundary nodes: **3**
- House 1 exterior binding: candidate only
- House 2 exterior binding: candidate only
- House 3 exterior binding: unproven

### Critical interpretation

The graph is now a stable spatial evidence layer between the SH3D census and future route validation:

`SH3D door → adjacency edge → graph nodes → candidate path`

It is **not**:

`SH3D door → runtime route`

No logical application door is bound to a physical edge yet. That binding remains the next reconciliation task.

### Findings

1. Exterior is explicit instead of being represented by an empty room side.
2. House 1 and House 2 have physical exterior-door candidates.
3. House 3 has no proven exterior door in this census.
4. Disconnected components are retained as evidence rather than repaired with invented links.
5. No runtime, canonical SH3D, candidate SH3D, camera, or route implementation was changed.
