### C. Cinematic WebGL layer — PRESENT AS PROTOTYPE, NOT SH3D RUNTIME

The repository contains:

- `js/reference-3d/cinematic-3d-adapter.js`
- `js/reference-3d/cinematic-3d-renderer.js`
- `js/home/house-camera-rig.js`
- `js/home/house-world-scroll.js`

The adapter is renderer-neutral and can mount a declared cinematic world.

The renderer is a native WebGL2 proxy renderer. It generates low-poly proxy cubes for declared world slots; it does **not** render `HomeFinder.sh3d`.

`cinematic-ui.js` calls `window.hfCinematic3D?.mount(...)`, but the current application pages do not load `cinematic-3d-adapter.js` or `cinematic-3d-renderer.js` directly.

Therefore the WebGL proxy layer is present in source but is not currently the authoritative application 3D runtime.

**Status: GAP — integration scaffold only**

## Important repository discrepancy corrected

The previous `docs/json/3d-contract.json` stated that exactly one `.sh3d` could exist in the checkpoint.

The actual checkpoint contains three SH3Ds:

1. `master/HomeFinder.sh3d` — canonical runtime authority
2. `3d/imports/Additional.sh3d` — reconciliation evidence
3. `3d/staging/HomeFinder-merge-candidate-Additional-reconciled.sh3d` — reconciliation evidence

The audit corrected the contract and verifier rather than deleting evidence artifacts.

The new rule is:

> Only `master/HomeFinder.sh3d` is physical runtime authority. SH3Ds under `3d/imports` and `3d/staging` may remain as evidence, but runtime code must never load them as authority.

This preserves evidence lineage while eliminating authority ambiguity.

## Phase-1 conclusion

The project is **not yet ready for full 3D route implementation** because the existing runtime has two distinct systems:

1. a standalone Sweet Home 3D viewer that can render the canonical model;
2. a cinematic/presentation layer that can animate camera state but currently renders proxy geometry rather than the canonical SH3D.

They are not yet reconciled into one physical navigation runtime.

The smallest next implementation should therefore be:

1. establish a single application-owned 3D runtime entry point;
2. make it consume only the canonical SH3D;
3. reconcile the 15 canonical cameras against the application's camera/POV contract;
4. create a machine-readable physical portal graph from proven G1 evidence;
5. implement route execution only for validated edges;
6. enforce the house topology and role/session contract at the destination boundary;
7. keep House 2 ↔ House 3 direct traversal impossible by construction.
