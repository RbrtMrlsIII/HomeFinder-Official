# 5.5G.6J — Inter-House Navigation UX Integration

Status: IMPLEMENTED + VERIFIED (static/end-to-end contract level)

## Objective

Expose the controlled inter-house navigation model through the canonical
HomeFinder 3D viewer without changing the physical SH3D authority or
bypassing route authorization.

## Implemented

- Added House 1 / House 2 / House 3 navigation controls to the viewer.
- Added accessible pressed-state and live status feedback.
- Viewer imports the canonical inter-house navigation module.
- Role is read from the existing session role boundary with guest fallback.
- Destination access is rechecked by the canonical route-access contract.
- House 2↔House 3 journeys visibly resolve through House 1 rather than
  silently performing a direct transition.
- The viewer does not mutate the SH3D model during transport.
- Existing vendor Sweet Home 3D runtime files remain unchanged.

## Architectural invariants

1. House 1 is the inter-house transit hub.
2. House 2↔House 3 direct travel remains forbidden.
3. Physical movement never changes identity or role.
4. Destination access is rechecked before application navigation.
5. Logical transport is not presented as physical SH3D portal evidence.

`docs/contracts/...` paths while their canonical contracts now live under

contracts themselves. The three verifiers then passed.
