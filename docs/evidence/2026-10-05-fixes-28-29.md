**Grade:** emulator-proven. **Not deployed, not live-proven.** No credential was used.

## What changed

| Defect | Fix | Proven by |
|---|---|---|
| #29 every client self-create of `users/{uid}` denied | Create rule reads the incoming document's own keys (`resource` is null on create); allows `idVerification` only as `{status: "none"}`; `accountType` must also be owner/seeker | Registration payload that `js/auth.js` writes (merge and non-merge), owner profile; admin/broker/moderator/staff, mixed `accountType`, `verified`/`prcVerified`/`subscription`/`suspended`/unknown fields, pre-set KYC states and extra `idVerification` keys all refused |
| #28 P1 binding re-pointed | Bind once, in a transaction; another account gets `already-exists` | Re-bind by a caller with a matching email |
| #28 P2 identity proof skipped | Proof is `custom_id` = uid or an exact email match; without proof: no binding, no grant, status `pending_verification`; `custom_id` naming another account is rejected | No-email account, PayPal-no-email subscription, `custom_id` match and mismatch |
| #28 P3 unbound event lost | A HomeFinder-plan event with no binding fails (HTTP 400) so PayPal retries; other plans, unknown subscriptions and unhandled types are acknowledged | Retry after binding activates (attemptCount 2); foreign-plan, 404 and unhandled-type cases |
| #28 P4 duplicate while processing | `processingStartedAt` on the first ledger write **and** the ledger decision is the transaction's return value | Fresh-processing duplicate; three concurrent deliveries give one notice |
| #28 P5 grants vs provider state | Grant and revoke leave a live PayPal entitlement alone; the grant layer and audit (`providerEntitlementLive`) still record them | Live, cancelled and expired PayPal entitlements |
| #28 P6 sale events never notify | Subscription id resolves from `billing_agreement_id` first | `PAYMENT.SALE.COMPLETED` notifies |

## Found on the way

The webhook set `shouldProcess = true` inside a retried transaction callback and never reset it, so a concurrent duplicate whose first attempt was aborted was processed anyway (three deliveries produced three notices even with `processingStartedAt` set). Returning the decision from the transaction fixes it. The concurrency test caught it.

## Behavior changes to know

- A subscription with no proof (no PayPal email, or an account with no email) now stays pending and unbound; before, an ACTIVE one was bound and activated.
- A PayPal email that differs from the account email is still rejected, until the frontend sends `custom_id` = uid at subscription creation.
- Unbound HomeFinder events now return 400 so PayPal retries; retries stop being acknowledged-and-lost.

## Not proven

Deployed rules and Functions; real PayPal retry timing and event shapes beyond the mocked ones; the frontend does not send `custom_id` yet; there is no support tool to bind a verified-but-unproven subscription; the Edge port does not exist yet. Deploying the rules changes live registration behavior (it fixes it) and needs owner approval.
