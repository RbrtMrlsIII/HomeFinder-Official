# 5.5G.6L — Browser Verification Acceptance Gates

## Gate A — Infrastructure

PASS requires:

- Playwright installed from the repository's dependency model
- Chromium installed and launchable
- application startup mechanism documented
- browser version/environment recorded
- no production secrets required

## Gate B — Basic Browser Health

PASS requires:

- HomeFinder opens in Chromium
- canonical entry page loads
- required scripts/assets load
- no blocking startup error
- test can interact with the application

## Gate C — Navigation UX

PASS requires:

- House 1 → House 2 works through the actual UI
- House 1 → House 3 works through the actual UI
- House 2 → House 1 works
- House 3 → House 1 works
- House 2 → House 3 direct traversal is rejected
- House 3 → House 2 direct traversal is rejected

## Gate D — Role Preservation

For every supported role used by the matrix:

`role_before == role_after`

Physical/spatial movement must never change authenticated identity or role.

## Gate E — Authorization

A destination must be evaluated through the canonical authorization system.

A browser test must not grant access simply because it can navigate to a URL.

## Gate F — UI State

The browser must observe the expected destination presentation, not merely a changed URL.

Where relevant verify:

- active navigation state
- destination page/surface
- access/restriction state
- loading completion
- visible error state

## Gate G — Evidence

A successful run must provide compact results.

A failed run must provide enough evidence to diagnose the failure.

Preferred failure evidence:

- HTML report
- trace on retry/failure
- relevant screenshot
- console/network information where useful

## Gate H — CI

PASS requires the same critical suite to execute in the intended CI environment.

The local machine must not be the only environment capable of passing the tests.

## Gate I — Regression

Existing MJS verification remains green.

Browser verification supplements rather than replaces:

- route authority
- security authority
- role authority
- contract checks
- SH3D verification
- existing integration/data checks

## Gate J — Continuity

The repository must record:

- what was implemented
- environment used
- browser target
- test matrix
- result
- failures/limitations
- evidence location
- next phase

## Final Verdicts

Use only one of:

### PASS
All required gates pass.

### PASS WITH LIMITATION
Required engineering behavior passes, but a non-critical environment or coverage limitation remains explicitly documented.

### BLOCKED
A required gate cannot be executed or verified.

### FAIL
A required behavioral or integrity assertion fails.

Do not call a browser phase PASS merely because Playwright installed successfully.
